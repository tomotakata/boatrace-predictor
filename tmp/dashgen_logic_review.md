## 1. 全体構造の整理

### 1-1. 15ステップ・パイプラインの依存グラフ

```
入力: entries[6] + racer_courses + environment
  │
  ├─ ① 基準ST (kijun_st)  ←── 入力のみ
  │     │
  ├─ ② 優勢順位D (yusei_rank)  ←── ①基準ST
  │     │
  ├─ ③ モーター順位 (motor_rank)  ←── 入力のみ
  │     │
  ├─ ④ 握り率 (nigiri_rate)  ←── 入力のみ
  │     │
  ├─ ⑤ 捲り完遂力差g (makuri_g)  ←── ①基準ST, ③モーター順位
  │     │
  ├─ ⑥ pre_EI (G除外) → pre_rank  ←── ②優勢順位D, ③モーター順位, 入力(成績)
  │     │
  ├─ ⑦ 握り発生率 (nigiri_hassei)  ←── ①基準ST, ④握り率, ⑥pre_rank, 環境(風)
  │     │
  ├─ ⑧ EI最終 (G加算)  ←── ⑥pre_EI + ⑦握り発生率(→G成分)
  │     │
  ├─ ⑨ P1 (1着率, 暫定)  ←── ①基準ST, ③モーター順位, 環境(風/波/季節)
  │     │
  ├─ ⑩ 1号被弾分析 (higaki)  ←── ⑧EI, ③モーター順位, racer_courses
  │     │
  ├─ ⑪ 減衰係数 (damping_1c)  ←── ⑩被弾分析
  │     │  → ⑨P1を再計算（genshu1反映）→ P1確定
  │     │
  ├─ ⑫ 逃げ成立度 (nige_seiritsu)  ←── ⑤g, ⑦握り発生率, ⑩被弾分析
  │     │
  ├─ ⑬ TI (信頼指数)  ←── ⑨P1(確定), ⑫逃げ成立度, racer_courses(P2マトリクス)
  │     │
  ├─ ⑭ 着内率/2着期待  ←── ⑧EI, ⑬TI, ⑦握り発生率, ⑩被弾分析, ⑫逃げ成立度
  │     │
  └─ ⑮ 捲り負け率/抵抗/連帯艇  ←── 入力のみ(コース別成績)
```

### 1-2. 依存関係の層構造（実装順序）

| 層 | ステップ | 依存先 | 備考 |
|---|---|---|---|
| L0 (入力のみ) | ①基準ST, ③モーター順位, ④握り率, ⑮捲り負け率 | なし | 並列計算可 |
| L1 | ②優勢順位D, ⑤捲り完遂力差g | ①, ③ | ①③完了後 |
| L2 | ⑥pre_EI → pre_rank | ②, ③ | ②完了後 |
| L3 | ⑦握り発生率 | ①, ④, ⑥ | ⑥完了後 |
| L4 | ⑧EI最終 | ⑥, ⑦ | ⑦完了後 |
| L5 | ⑨P1(暫定) | ①, ③ | ①③完了後（⑪で再計算） |
| L6 | ⑩被弾分析 | ⑧, ③ | ⑧完了後 |
| L7 | ⑪減衰 → ⑨P1確定 | ⑩ | ⑩完了後 |
| L8 | ⑫逃げ成立度 | ⑤, ⑦, ⑩ | ⑤⑦⑩完了後 |
| L9 | ⑬TI | ⑨(確定), ⑫ | ⑨⑫完了後 |
| L10 | ⑭着内率/2着期待 | ⑧, ⑬, ⑦, ⑩, ⑫ | ⑬完了後 |

**クリティカルパス**: ① → ② → ⑥ → ⑦ → ⑧ → ⑩ → ⑪ → ⑨確定 → ⑫ → ⑬ → ⑭

### 1-3. 循環依存の有無

**循環なし**。⑨P1は暫定→⑪で再計算という2パス構造だが、⑪→⑨は1回のフィードバックで収束する設計（反復なし）。

### 3-3. 決定論性の確認

資料の記述通り、以下の点で決定論性が保証される：
- 乱数・時刻・ハッシュ依存なし
- 順位付けは「自分より上の個数+1」で一意
- ソートは安定（同点タイ・次順位スキップ）
- 同一入力 → 同一出力

**ただし注意点**:
- 浮動小数点の丸め順序が結果に影響する可能性あり（`round()` の挙動はPythonバージョンで異なる場合がある）
- `desc_score` の同点処理で、同値が3つ以上ある場合の挙動が明示されていない（「自分より大きい個数+1」で一意だが、同点者全員が同じスコアを得る）

## 6. 資料の品質評価

### 6-1. 良い点

1. **計算式が明確**: 各ステップの入出力と計算式が疑似コードで明示されている
2. **依存関係が明確**: パイプライン図で全体の流れが把握できる
3. **決定論性の保証**: 乱数不使用・同点処理の明示
4. **用語の対応表**: first_prob/place_prob/second_expect 等の内部名と表示名の対応が冒頭にある

### 6-2. 不足・要確認点

1. **会場設定が2会場のみ**: 実装には v587_full_spec.md の24会場分が必須
2. **季節係数SEASON**: 蒲郡の例のみ。全会場分の定義が不明
3. **R番号係数RNUM**: 蒲郡の例のみ。use_rnum=True の会場（蒲郡のみ？）の定義が不明
4. **GENSHU_FLOOR**: 蒲郡の例のみ
5. **枠補正テーブル I**: 一部の(級,枠)ペアのみ。全パターンが不明
6. **f_keisu3 の詳細**: dashgen_logic_full.md では言及なし。v587_full_spec.md に記載あり
7. **風補正 wind_mult / 波補正 wave_mult**: 「未適用（既定1.0）」との注記あり（v587_full_spec.md V-5）
8. **季節モーター**: 「未使用」との注記あり
9. **平和島の mot_w=(5.0, 3.0)**: 他会場が (0.45, 0.55) 等の範囲なのに対し異常値。タイポの可能性
10. **2号の差し率**: ⑦握り発生率の3号計算で使用するが、入力スキーマに `sashi` はコース別決まり手カウント（整数）であり、「差し率%」への変換方法が不明確

### 6-3. v587_full_spec.md との不整合
